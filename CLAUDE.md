# Sunnyfolk for Roblox

The Roblox version of [Sunnyfolk](https://github.com/lschandler81/game), a cosy animal town for
children aged 5 to 9. Players pick an animal, wander the town square, collect coins, chat with
the residents, buy hats from Clover and build a house at Home Pond. The code is Luau, kept in
this repo and synced into Roblox Studio with Rojo (`default.project.json`).

Read these before changing anything:

- `README.md`: what's in the game and where the code lives.
- `docs/roblox-studio.md`: setting up and testing in Studio (Rojo, importing the models,
  saving, the wardrobe check, keeping it safe for children).
- `docs/characters.md`: how the character models fit together.
- `docs/BUILD_STEPS.md`: the build plan. Work one step at a time with `/step N`.
- `PROGRESS.md`: which steps are done and what's left for the owner to do.

## Folder layout

```
assets/characters/   the animals, hats and clothes exported from the web game (.glb), and
                     sunnyfolk.json (coats, hats, clothes, residents and their lines)
assets/models/       a place for a backup of the models once they're imported into Studio
docs/                guides and the build plan
tools/               make_mesh_layout.py writes src/shared/MeshLayout.luau from the .glb files

src/shared/   -> ReplicatedStorage.Sunnyfolk (used by the server and every player)
  Config.luau            every number and setting: places, coins, speeds, plots, test switches
  Looks.luau             easy reading of sunnyfolk.json
  Models.luau            finds the imported models in ReplicatedStorage.SunnyfolkModels
  MeshLayout.luau        where every mesh sits (generated: never edit by hand)
  CharacterBuilder.luau  builds a rigged animal with its colours, clothes and hat
  Build.luau             parts in the Sunnyfolk colours, and props (lamps, trees, houses)
  Houses.luau            the choices for players' houses, and building one

src/server/   -> ServerScriptService.Sunnyfolk
  Main.server.luau       starts everything
  Town.luau              builds the town square and Home Pond
  PlayerData.luau        saves each player's data (DataStore)
  Avatars.luau           gives each player their animal
  Residents.luau         the residents: strolling and talking
  Coins.luau, HatShop.luau, Homes.luau   check coins, hat purchases and houses
  Wardrobe.luau          the Studio-only fitting room (Config.WARDROBE_CHECK)

src/client/   -> StarterPlayer.StarterPlayerScripts.Sunnyfolk
  Main.client.luau       starts everything on each player's computer
  Ui.luau                the shared look of every screen (and Ui.fitToScreen for phones)
  Chooser, Hud, HatShop, HomeDesigner, Prompts, Talk, Coins, Homes, Animator, Controls
```

The Remotes (RemoteEvents and RemoteFunctions) are declared in `default.project.json`, which also
maps `assets/characters/sunnyfolk.json` into the game as `ReplicatedStorage.Sunnyfolk.CharacterData`.
The imported models live in the place, in `ReplicatedStorage.SunnyfolkModels`, which Rojo leaves
alone.

## Rules

- **The server decides.** Everything about coins, items, houses, progress and purchases is
  checked and changed on the server. Never trust the client for a price, an amount, a reward or
  who owns something. Every remote handler checks the type, range, ownership and rate of what
  it's sent.
- **No text boxes of our own.** Players only talk through Roblox's own chat. Names shown in the
  game are Roblox display names.
- **No pressure around buying.** No random rewards, no countdown timers, no "last chance" or
  other pressure wording near anything that costs money.
- **Buying is fair.** Purchases only go through Roblox's own purchase prompt, shown when the
  player taps a product. Each receipt is granted once, and the player's data is saved before it
  counts. Nothing that needs Robux blocks a place, a friendship or a story; coins stay earnable
  by playing.
- **Every screen must fit a phone.** Use `Ui.fitToScreen`, make touch targets at least 44
  pixels, and keep clear of the thumbstick (bottom left) and jump button (bottom right).
- **Old saves must keep loading.** Every new field in PlayerData gets a default and is tidied
  when it's loaded (and goes through the save version upgrade, once there is one).
- **Keep it light.** No loop that runs every frame for every player or part without a distance
  limit, and everything made for a player is cleaned up when they leave.
- **Numbers live in `src/shared/Config.luau`**, not scattered through the code.
- **Never edit `assets/characters/` or `src/shared/MeshLayout.luau`.** The models come from the
  web game's exporter, and the layout file is generated by `tools/make_mesh_layout.py`.
- **Comments are plain, simple English**, like the rest of the repo: say what a thing is for,
  in short sentences.
- **Make every change in this repo.** Scripts edited inside Studio aren't copied back.

## How to work

- One build step per session. Read the step in `docs/BUILD_STEPS.md`, stay inside the files it
  names, and show a plan first when it says "plan first".
- The owner does the testing in Studio: `rojo serve` in this folder, then Plugins > Rojo >
  Connect, then Play. Claude can't press Play.
- After each change, check the project still builds (`rojo build -o /tmp/sunnyfolk-check.rbxl`),
  then give a short checklist to test in Studio.
- Commit only after the owner says the Studio test passed, then add a line to `PROGRESS.md`.
- The web game sits next to this repo at `../game`. Copy its designs and numbers; the
  JavaScript itself doesn't carry over.
