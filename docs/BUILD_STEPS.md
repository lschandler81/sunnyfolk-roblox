## How to work with Claude Code on this repo

- **One step, one session.** Start each session with `/step N`. Do Step 1 first, because it creates CLAUDE.md.
- **"Plan first" steps.** Claude Code shows its plan and waits for your OK before it changes any file.
- **You do the testing.** Claude Code edits the files but cannot press Play. For each step: run `rojo serve` in the repo, connect from Studio (Plugins, Rojo, Connect), press Play, and check the "Done when" line.
- **Commit after every step that passes.** Make a git tag before the two big ones, steps 8 and 21, so you can roll back.
- **Do not let it touch** `assets/characters/` or `src/shared/MeshLayout.luau`. The layout file is generated by `tools/make_mesh_layout.py`, and the models are imported once into Studio.
- **Scripts edited inside Studio are not copied back** to the repo. Make every change in the repo.
- **"You" steps** are things only you can do: Studio, the Creator Dashboard, your phone.
- **The web game** sits next to this repo at `../game`. Prompts point Claude Code at its files so it copies the design and numbers. The JavaScript itself does not carry over.

## Part 1: solid core (steps 1 to 12)

Steps 1 to 8 make the game safe, measurable and smooth on phones. Steps 9 to 12 give players something to do. Nothing is sold yet.

### Step 1: Add CLAUDE.md

**Why:** every later session starts with the same rules. **Files:** new `CLAUDE.md`.

```text
Read README.md, docs/roblox-studio.md and docs/characters.md. Create CLAUDE.md at the repo root with: what this project is (the Roblox version of Sunnyfolk for children aged 5 to 9, built with Rojo); the folder layout; and these rules. The server decides everything about coins, items, houses and purchases, and never trusts the client. No text boxes of our own, only Roblox chat. No random rewards, countdown timers or pressure wording around purchases. Every screen must fit a phone. Numbers live in src/shared/Config.luau. Never edit assets/characters or src/shared/MeshLayout.luau. Comments are in plain simple English like the rest of the repo. After each change, give me a short checklist to test in Studio. Then commit.
```

**Done when:** CLAUDE.md exists and is committed.

### Step 2: Make saving safe

**Why:** money will flow through this, and today a failed load lets a player continue on a blank, unsaved profile. **Files:** `src/server/PlayerData.luau`.

```text
Plan first. In src/server/PlayerData.luau, make saving safe before we sell anything. (1) Add a session lock so the same player cannot be loaded on two servers at once: keep a lock (server JobId and a time) inside the saved data using UpdateAsync, wait or refuse if another live server holds it, and release it on leaving and in BindToClose. (2) Make save read the old value in UpdateAsync and merge, so older data never overwrites newer data. (3) Add a version number to Data and a migrate function so existing SunnyfolkPlayers1 saves still load. (4) If a load fails after the retries, kick the player with a kind message instead of letting them play unsaved, but in Studio with API access off keep today's behaviour (play on, nothing saved). (5) Add PlayerData.saveNow(player) for use right after a purchase. Keep the store name and all existing fields. Give me a Studio test checklist that includes a quick leave and rejoin.
```

**Done when:** coins, hat and home survive a leave and rejoin, and a rejoin within seconds does not lose or duplicate anything.

### Step 3: Guard the remotes

**Why:** the buy and wear hat remotes have no rate limit, and Double Coins will make coins worth more. **Files:** new `src/server/RemoteGuard.luau`; edit `Coins.luau`, `HatShop.luau`, `Homes.luau`, `Avatars.luau`, `src/shared/Config.luau`.

```text
Add src/server/RemoteGuard.luau: a small helper that allows at most N calls per time window per player per remote, and ignores the rest quietly. Use it on BuyHat, WearHat, CollectCoin, Play and SetHome (keep the existing 1 second and 2 second checks and the per-coin cooldown). Add Config.COIN_MAX_PER_MINUTE (start at 40) and refuse pickups above it. Keep normal play unaffected. Give me a way to test by spamming BuyHat from a local script in Studio.
```

**Done when:** normal play feels the same, and a spam loop gets ignored.

### Step 4: Add analytics

**Why:** you cannot decide anything in Part 4 without numbers. **Files:** new `src/server/Analytics.luau`; small hooks in `Avatars.luau`, `Coins.luau`, `HatShop.luau`, `Homes.luau`.

```text
Add src/server/Analytics.luau wrapping Roblox's AnalyticsService, with every call in pcall. First check the current Roblox documentation for the exact API names. Log an onboarding funnel: 1 joined, 2 chose an animal, 3 first coin, 4 first hat bought, 5 first home. Log economy events for coins earned (source: pickup) and spent (sink: hat). Add hooks in the existing server scripts with the smallest change. Add a Studio-only print of each event so I can see them while testing.
```

**Done when:** a test run prints all five funnel steps in order.

### Step 5: Measure, then lighten the town (plan first)

**Why:** the town is built from parts at run time, lamps carry point lights, and I found no streaming setting in `default.project.json`. **Files:** `default.project.json`, `src/server/Town.luau`, `src/shared/Build.luau`.

```text
Plan first, change nothing yet. Add a Studio-only debug print after Town.build() that counts Workspace descendants by class (BaseParts, MeshParts, Models, PointLights) and report the numbers. Then propose changes and wait for my OK on each: (a) StreamingEnabled with a sensible StreamingTargetRadius in default.project.json, checking that coins, residents, homes, Talk and Animator do not break when parts stream in and out; (b) fewer or cheaper PointLights on the lamps in Build.luau; (c) CastShadow off on small decor; (d) simple collision shapes. Implement one at a time.
```

**Done when:** you have the counts, and after the agreed changes you can walk every road and Home Pond with nothing missing and a smoother frame rate on your phone than in Part 0, step D.

### Step 7b: Controller and console pass

```text

Nothing may need hovering or a mouse. On a console (GuiService:IsTenFootInterface()), make text and buttons bigger so they read from across a room, with the sizes in Config. Give me a Studio checklist using a plugged-in or Bluetooth Xbox or PlayStation controller.
```

**Done when:** you can play from the welcome screen through buying a hat and designing a house using only a controller in Studio, then on a real console if you have one. After that, tick Console in Experience Settings (no need to publish as a new experience).

First Story, in order: (1) say hello to Clover, who sends you to Fern's Garden, and the Garden's gate opens for you then (no 6-sunshine wait for new players); (2) plant your first seed; (3) water it and pick it.
